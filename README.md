# Lemon Agent

**Free tools · honest measurements · agentic services.**

A small house for working with agents — the counterpart to LEMON AUDIO.
Members ship under one name so each carries the others: numbered failure
lists you run as subtraction passes, published measurements, and services
agents can call directly.

> **Status: private, pre-launch.** Both lists are v0; the author curation
> pass hasn't happened yet. The repo goes public when the first list does.

## House rules

1. **The user-use check.** Nothing ships without a working answer to
   *"how would a user actually make use of this, today?"* — a copyable
   prompt, an install command, or a key. If the honest answer is "they
   can't yet," the member's page says so plainly instead of pretending.
2. **No shared infrastructure before two members exist.** The house is a
   name and a catalog over things that ship anyway; the moment it demands
   its own infrastructure first, it has inverted.

## Use the lists

**In any chat assistant** — each list's "How to use it" section carries a
paste-ready prompt; add the list and your draft/PR and go.

**As Claude Code skills:**

```sh
git clone https://github.com/chronick/lemon-agent
cp -r lemon-agent/skills/prose-failure-list ~/.claude/skills/
cp -r lemon-agent/skills/agent-workflow-failure-list ~/.claude/skills/
```

Then: *"run the prose failure list on drafts/my-post.md"* or *"run the
workflow failure list on this PR"*.

**In an agent or pipeline** — raw markdown at `/lists/*.md` (stable
PF-NN / AF-NN ids), machine catalog at `/catalog.json`, index at
`/llms.txt`. Advisory passes only: they report, they never gate.

## Layout

```
lists/        Canonical markdown — the lists ARE the product; site + skills render from here
skills/       Installable Claude Code skills (list.md copies are generated by `npm run sync`)
src/          Astro site (static, zero-JS) — LEMON AUDIO visual language, light rendition
public/       catalog.json · llms.txt · favicon — the agent-facing surfaces
```

The site is fully static: markdown in git, HTML at build time. No
server, no database, no client JavaScript. Dark mode is the native
LEMON AUDIO look (deep space, chartreuse, scan lines); light mode is
the same language in daylight.

## Develop

```sh
npm install
npm run dev      # local site at http://localhost:4321
npm run build    # static build to dist/
```

`npm run sync` (runs automatically before dev/build) copies `lists/*.md`
to `public/lists/` and into each skill directory — edit only `lists/`.

## Ship checklist (flip to public)

1. **Curation pass on each list** — cut, rewrite, reorder; a 15-entry
   list you'd defend beats a 24-entry list you'd shrug at. Curation
   happens in `lists/*.md` here. (Tracked: vault-1lc71 for the AF list.)
2. Flip `status: draft` → `published` in frontmatter and catalog.json;
   run `npm run sync` so skills and raw copies match.
3. Pick a license (owner call) and add `LICENSE`.
4. Decide deploy target (Cloudflare Pages vs GitHub Pages project site)
   and set `site`/`base` in `astro.config.mjs`; wire a privacy-respecting
   analytics beacon at the same time.
5. `gh repo edit --visibility public`, deploy, cross-link from
   pathgrip.net, log the ship in tradewind (starts the probe clock).
6. **pathgrip's user-use answer**: ship its public docs page + self-serve
   keys as the next member — until then its card stays honest about
   "not yet."
